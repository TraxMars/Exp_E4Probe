## 4. 结论

**事先设定的判据**（README.md C1 一节，在启动前写好）：只有在两个数据集上都满足以下两条时，才认为某一层有效：(a) test nms0 Dice 的 3 seed 均值比 V0 高 0.4 以上（约为 V0 标准差的 2 倍）；(b) 逐病例配对差值不跨 0。另外参考最后 5 次验证的均值。否则编码器 probe 这条线停止。

| 层级 | 数据集 | (a) 均值差 > +0.4 | (b) 病例配对区间不跨 0 | 判定 |
|---|---|---|---|---|
| E4 | LA_8l | +0.27（89.65 vs 89.38）→ 不通过 | [−0.07, +0.62] → 不通过 | 不通过 |
| E4 | Pancreas_6l | −0.16（80.47 vs 80.64）→ 不通过 | [−0.83, +0.50] → 不通过 | 不通过 |
| E3 | LA_8l | −0.30（89.08 vs 89.38）→ 不通过 | [−0.97, +0.37] → 不通过 | 不通过 |
| E3 | Pancreas_6l | +0.05（80.68 vs 80.64）→ 不通过 | [−0.50, +0.60] → 不通过 | 不通过 |

- **决策**：E4 和 E3 都不通过。按事先规定，**停止编码器边界 probe 这条线**，λ 和层级都不再调。
- **E4 / LA 有小幅正向变化，尚不能下结论**：3 个 seed 的 nms0 Dice 配对差值都为正（+0.42、+0.09、+0.32），seed 间标准差从 V0 的 0.20 降到 0.03，nms0 HD95 −1.73 ± 1.59，最后 5 次验证 +0.63 ± 0.71。但均值 +0.27 没有达到 0.4；病例级区间跨 0；nms1 Dice 只高 +0.14 ± 0.23；HD95 的配对差值标准差和均值一样大；而且 Pancreas 上方向相反（−0.16）。V0 同 seed 重复跑本身就有 0.3–1.2 的差异（见 `/aita_data/home/aita_duanxuelong/SSL_research_review_2026-11-06.md`），+0.27 落在这个范围内。
- **E3 / LA 后期验证变差（数据直接支持）**：3 个 seed 最后 5 次验证的配对差值都为负（−1.44、−1.04、−2.76），均值 −1.74 ± 0.90。第 13000–15000 步的 33 次验证中，有 8 次低于 85（其中 6 次来自 seed 1337），而 V0 在同一区间的最低值是 87.10。test nms0 也是 3 个 seed 都为负（−0.30 ± 0.23），但幅度在 0.4 以内。由于 test 用的是在 test.list 上挑出的最佳验证步，后期波动对它的影响被削弱了。
- **Pancreas**：两个层级的 test Dice 变化（E4 −0.16 ± 0.28，E3 +0.05 ± 0.30）都在 V0 的 seed 间标准差附近，正负号在不同 seed 间也不一致，**尚不能下结论**。按判据看，也就是没有效果。
- **诊断量**：band_iou、ce_pl_in、teacher_err_gt_band、conf_wrong_095 与 V0 同 seed 的数值接近，例如 LA conf_wrong_095：V0 为 0.7343 / 0.7084 / 0.7115，E4 为 0.7364 / 0.6946 / 0.7125，E3 为 0.7292 / 0.6993 / 0.7047。Teacher 在边界带内"高置信但错误"的比例没有变化。
- **grad_ratio（数据）**：
  - E4 后期 ‖∇(λL_b)‖ / ‖∇L_sup‖ 为 0.15（LA）和 0.17（Pancreas）；E3 为 0.57（LA）和 0.36（Pancreas），而且训练后期比前 2000 步更大（LA 从 0.28 升到 0.57）。
  - grad_cos 都为正（0.12–0.37）。
  - E3 probe 的 boundary_dice 损失更低（0.35，E4 为 0.43–0.44）。
- **推测（未验证）**：
  - 在同一个 λ = 0.03 下，E3 的边界梯度在 1/4 分辨率的浅层编码器上占到监督梯度的一半以上，已经不是一个小的辅助项。这可能就是 LA 后期验证变差的原因。
  - E3 的边界预测得更准（损失更低），分割却没有更好。这和 11-11 的分析一致：一层特征里边界信息更多，不等于对这一层做边界监督就有收益。
  - 要验证这个推测，需要把 E3 的 λ 降到和 E4 梯度比相当的水平（约 0.008）。但按判据这条线已经停止，**不建议**为此再开 run。

## 5. 问题与风险
1. **模型选择和评估用的是同一个 test.list**：最佳验证 Dice 等于 test nms0 Dice，所以表中的 test 结果偏乐观。V0 和 C1 用的是同一套协议，配对比较仍然成立，但不能和论文里的数字直接对比。
2. **病例配对区间的计算方式是事后定的**：README 只写了"不跨 0"，没有规定是 t 区间还是 bootstrap，也没规定是否先对 seed 求平均。这里给了两种算法（病例级 3 seed 平均和 60 个差值合并），所有组合的结论都一样（都跨 0），不影响判定。
3. **E4 / seed_1337 / Pancreas_6l 第 1 步 ce 有末位差异**（约 6e-8，见 3.7）：在验收容差内，和 V0 本身同 seed 重跑的差异属于同一类，不影响结论。
4. **11-11 的自动日志没有生成**：`tools/cron.log` 中 11-11 23:55 的记录是 "API Error: Connection refused"，claude 退出码 1。另外，自动日志只覆盖 `Baseline/MT_DS_DICE` 和 `Exp_BCCP/MT_DS_DICE` 两个目录，**不包括** `Exp_E4Probe/MT_DS_PL_C1`，所以 C1 只有这篇手动日志。
5. **本日志目录是未跟踪文件**：`scripts/launch.py` 检查工作树时只忽略未跟踪的 `Results*`。如果之后在这个目录里再用 launch.py 启动 run，未跟踪的 `实验日志/` 会让启动被拒绝。需要先提交日志，或者把它加入忽略规则。
6. **结果目录未跟踪**：`Results_C1_E4/`、`Results_C1_E3/` 未跟踪，这和 V0、V1 的处理方式一样。
